# Contributing

Thanks for your interest in improving `claude-branch-interview`, a Claude Code skill that interviews an engineer about the code written in a branch.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting issues

- **Bugs:** open an issue with the **Bug report** template. Include your Claude Code version, the steps to reproduce, and what you expected.
- **Feature ideas:** open an issue with the **Feature request** template. Describe the problem before the solution.
- **Security vulnerabilities:** do not open a public issue. Follow [SECURITY.md](SECURITY.md).

Search existing issues first to avoid duplicates.

## Making changes

1. Fork the repository and create a branch from `main`.
2. Keep each pull request focused on one change.
3. Write commit messages in the [Conventional Commits](https://www.conventionalcommits.org/) format, for example `feat: ask follow-up questions about tests` or `fix: handle branches with no diff`.
4. Update `README.md` when you change how the skill is installed or used.
5. Open a pull request against `main` and fill in the template.

## Review

Pull requests need approval from a code owner (see [`.github/CODEOWNERS`](.github/CODEOWNERS)) before merge. Expect questions; they are part of the process, not a rejection.
